# راهنمای منطق بیزینس و تطبیق فرآیند تخصیص آگهی به آژانس (ویژه توسعه‌دهنده بک‌اند)
### Ad Assignment Flow & Two-Sided Business Logic Specification

این سند به عنوان راهنمای فنی و مقایسه‌ای برای **توسعه‌دهنده بک‌اند (Back-end Developer)** تهیه شده است تا منطق تجاری (Business Logic)، ماشین وضعیت (State Machine) و نحوه تعاملات هم‌زمان بین **کاربر واگذارکننده (مالک آگهی)** و **آژانس املاک (دریافت‌کننده آگهی)** را با صفحات پیاده‌سازی‌شده در فرانت‌اند و استوری‌بوک تطبیق دهد.

---

## ۱. جدول مقایسه‌ای منطق دو سمت (User vs Agency Matrix)

| مرحله / وضعیت | رفتار و دسترسی سمت **کاربر واگذارکننده** (User) | رفتار و دسترسی سمت **آژانس املاک** (Agency) | تغییرات دیتابیس و وضعیت سیستمی |
| :--- | :--- | :--- | :--- |
| **۱. ثبت و واگذاری اولیه** | هنگام ثبت آگهی، کاربر گزینه «واگذاری به آژانس» را انتخاب کرده و یک آژانس مشخص را برمی‌گزیند. | نوتیفیکیشن دریافت آگهی جدید دریافت می‌کند. آگهی در تب درخواست‌های جدید (`allocation`) نمایش می‌یابد. | رکورد جدید در جدول `agency_advertise_assignments` با وضعیت `pending` ایجاد می‌شود. |
| **۲. در انتظار تایید آژانس** | آگهی با برچسب زرد «در انتظار تایید آژانس» نمایش داده می‌شود. کاربر حق لغو واگذاری دارد ولی امکان ویرایش مستقیم ندارد. | آژانس می‌تواند آگهی را بررسی کند، پیش‌نمایش ببیند، با مالک تماس بگیرد یا چت کند. | تایمر مهلت بررسی (مثلاً ۲۴ ساعت) فعال می‌شود. وضعیت: `wait_for_agency`. |
| **۳. لغو توسط کاربر (قبل تایید)** | کاربر از طریق باتم‌شیت «لغو واگذاری»، درخواست را پس می‌گیرد و می‌تواند آن را به آگهی شخصی تبدیل یا حذف کند. | آگهی از کارتابل بررسی آژانس خارج شده و پیام لغو برای آژانس ثبت می‌شود. | وضعیت به `cancelled_by_user` تغییر می‌کند. |
| **۴. رد آگهی توسط آژانس** | آگهی به «در انتظار ثبت مجدد» تغییر وضعیت می‌دهد. کاربر با مشاهده دلیل رد، می‌تواند آن را شخصی منتشر کند یا به آژانس دیگر بسپارد. | آژانس دلیل رد آگهی (قیمت نامتعارف، عکس نامناسب و...) را ثبت کرده و آگهی از کارتابل فعال او خارج می‌شود. | وضعیت: `agency_rejected` (فرانت: `wait_for_repost`). مهلت ۷ روزه برای اقدام کاربر فعال می‌شود. |
| **۵. تایید و انتشار توسط آژانس** | آگهی به وضعیت «منتشر شده» درمی‌آید. نام آژانس و مشاور روی آگهی درج شده و تاریخ انتشار و انقضا نمایش داده می‌شود. | آژانس نحوه مدیریت (مستقیم یا تخصیص به مشاور) را تعیین کرده، با کسر سهمیه پکیج خود آگهی را در بونگا منتشر می‌کند. | وضعیت: `published`. یک سهمیه از پکیج آژانس کسر و تاریخ انقضا (مثلاً ۳۰ روز) ست می‌شود. |
| **۶. درخواست توقف انتشار از سوی کاربر** | کاربر دکمه «درخواست توقف انتشار» را زده و در صفحه اختصاصی دلیل خود (معامله شد، انصراف و...) را ارسال می‌کند. | نوتیفیکیشن دریافت درخواست توقف دریافت می‌کند. می‌تواند توقف را تایید یا رد کند. | وضعیت: `stop_requested` (فرانت: `wait_for_stop`). آگهی تا تصمیم آژانس فعال می‌ماند. |
| **۷. تایید توقف یا حذف مستقیم آژانس** | آگهی با وضعیت قرمز «حذف شده» نمایش داده می‌شود. کاربر دکمه «ثبت نتیجه درخواست» را می‌بیند تا اعلام کند معامله انجام شد یا خیر. | آژانس پیگیری آگهی را پایان می‌دهد یا معامله را ثبت و آگهی را از حالت عمومی برمی‌دارد. | وضعیت: `agency_deleted_pending_review` (فرانت: `deal_confirmation`). مهلت پاسخگویی کاربر فعال می‌شود. |
| **۸. ثبت نتیجه معامله توسط کاربر** | در صفحه اختصاصی «نتیجه درخواست»، کاربر اعلام می‌کند معامله با این آژانس «موفق بود» یا «ناموفق بود». | نتیجه و رضایت‌سنجی در آمار عملکرد آژانس/مشاور، رتبه‌بندی و گزارشات کمیسیون منعکس می‌شود. | وضعیت: `deal_result_submitted`. رکورد نتیجه نهایی در سیستم قطعی می‌شود. |
| **۹. انقضا و بایگانی آگهی** | پس از اتمام مهلت انتشار، آگهی «بایگانی شده» می‌شود. کاربر دکمه «بازیابی آگهی» دارد. | آگهی از لیست آگهی‌های عمومی آژانس خارج و به بخش آرشیو منتقل می‌شود. | وضعیت: `archived`. مهلت ۳۰ روزه بازیابی قبل از حذف کامل فعال می‌شود. |
| **۱۰. حذف دائم پس از انقضای بازیابی** | آگهی به طور دائم منقضی و حذف شده است و دکمه عملیاتی برای فعال‌سازی ندارد. | آگهی در تاریخچه آرشیو باقی می‌ماند. | وضعیت نهایی: `deleted`. |

## ۲. بررسی ۱۰ وضعیت پیاده‌شده در UI و استوری‌بوک (Storybook States)

تمامی این ۱۰ وضعیت در کامپوننت فرانت‌اند `AgencyAssignedUserAdView.tsx` و استوری‌بوک `AccountMyAdStatePage.stories.tsx` پیاده‌سازی شده‌اند و باید در بک‌اند پوشش داده شوند:

### ۱. وضعیت `منتشر شده` (`AgencyDocs_1_Published`)
* **کلید وضعیت:** `published`
* **منطق کاربری:** کاربر زمان انتشار و زمان باقی‌مانده تا انقضا را می‌بیند. آیکون پیش‌نمایش و دکمه رفتن به صفحه «درخواست توقف انتشار» فعال است.
* **انتظار از بک‌اند:** ارسال فیلدهای `published_at`, `expires_at`, `agency_name`, `consultant_name` در پاسخ آگهی.

### ۲. صفحه `درخواست توقف انتشار` (`AgencyDocs_2_StopPublishPage`)
* **آدرس صفحه فرانت:** `/account/my-ads/:id/stop-publish`
* **منطق کاربری:** صفحه مجزا با ۳ گزینه انتخابی:
  1. معامله انجام شده است
  2. دیگر تمایلی به انتشار آگهی ندارم
  3. دلیل دیگری دارم
* **انتظار از بک‌اند:** اندپوینت `POST /api/v1/me/advertisements/{id}/stop-request` با ورودی `{ reason, description }`. پس از ارسال، تگ `has_pending_stop_request: true` شود.

### ۳. وضعیت `در انتظار تایید آژانس` (`AgencyDocs_3_WaitForAgency`)
* **کلید وضعیت:** `wait_for_agency` (دیتابیس: `pending`)
* **منطق کاربری:** کارت هشدار زرد رنگ با نمایش نام آژانس و تایمر مهلت بررسی آژانس. دکمه لغو واگذاری فعال است.
* **انتظار از بک‌اند:** محاسبه زمان باقیمانده از مهلت بررسی آژانس و ارسال در پاسخ.

### ۴. باتم‌شیت `لغو واگذاری به آژانس` (`AgencyDocs_4_CancelAssignmentSheet`)
* **منطق کاربری:** تنها باتم‌شیت این بخش. دارای دکمه «لغو درخواست» و «انصراف».
* **انتظار از بک‌اند:** اندپوینت `POST /api/v1/me/advertisements/{id}/assignment/cancel`. حذف واگذاری و آزادسازی آگهی برای کاربر.

### ۵. وضعیت `در انتظار ثبت مجدد` (`AgencyDocs_5_WaitForRepost`)
* **کلید وضعیت:** `wait_for_repost` (دیتابیس: `agency_rejected`)
* **منطق کاربری:** باکس تایمر فرصت ثبت مجدد (مثلاً ۶ روز). دکمه «ثبت مجدد آگهی» با آیکون رفرش که دو گزینه پیش روی کاربر می‌گذارد: انتشار شخصی یا ارسال به آژانس دیگر.
* **انتظار از بک‌اند:** نگهداری دلیل رد آژانس (`reject_reason`) و مهلت زمانی ثبت مجدد.

### ۶. وضعیت `بایگانی شده` (`AgencyDocs_6_Archived`)
* **کلید وضعیت:** `archived`
* **منطق کاربری:** بج طوسی. متن مهلت بازیابی آگهی و دکمه بنفش «بازیابی آگهی».
* **انتظار از بک‌اند:** اندپوینت `POST /api/v1/me/advertisements/{id}/assignment/restore` جهت بازگردانی آگهی به چرخه فعال.

### ۷. وضعیت `حذف شده (آژانس آگهی را حذف کرده)` (`AgencyDocs_7_DeletedAgencyDeal`)
* **کلید وضعیت:** `wait_for_deal_confirmation` یا `deleted` با دلیل `agency_deal`
* **منطق کاربری:** هشدار بسته شدن آگهی توسط آژانس + مهلت پاسخگویی + دکمه هدایت به صفحه ثبت نتیجه.
* **انتظار از بک‌اند:** پرچم‌گذاری آگهی با `deleted_reason = 'agency_deal'` و فعال کردن وضعیت انتظار ثبت نتیجه.

### ۸. صفحه `ثبت نتیجه درخواست / معامله` (`AgencyDocs_8_DealResultPage`)
* **آدرس صفحه فرانت:** `/account/my-ads/:id/deal-result`
* **منطق کاربری:** صفحه مجزا با تاپ‌بار «نتیجه درخواست». دو گزینه رادیویی:
  * 👍 **معامله موفق بود** (`success`)
  * 👎 **معامله ناموفق بود** (`unsuccessful`)
* **انتظار از بک‌اند:** اندپوینت `POST /api/v1/me/advertisements/{id}/deal-result` جهت ثبت فیدبک کاربر و قطعی‌سازی وضعیت کمیسیون و آمار آژانس.

### ۹. وضعیت `حذف شده (انقضای مهلت بازیابی)` (`AgencyDocs_9_DeletedRecoveryExpired`)
* **کلید وضعیت:** `deleted`
* **منطق کاربری:** وضعیت پایانی. بدون هیچ دکمه عملیاتی برای ثبت مجدد.

### ۱۰. وضعیت `حذف شده (توقف به درخواست کاربر)` (`AgencyDocs_10_DeletedUserStopped`)
* **کلید وضعیت:** `deleted` با `deleted_reason = 'user_stopped'`
* **منطق کاربری:** نمایش تاریخچه اینکه آگهی پیرو درخواست توقف کاربر بسته شده است.

## ۳. دیاگرام ماشین وضعیت دیتابیس (State Transitions)

```
[ثبت اولیه آگهی]
       │
       ▼
 [ pending ] ────────(لغو توسط کاربر)───────► [ cancelled ]
       │
  (تایید آژانس) ────(رد آژانس)───► [ agency_rejected ]
       │                                     │
       ▼                                (پایان مهلت اقدام)
  [ published ]                              │
   │        │                                ▼
   │   (درخواست توقف کاربر)             [ archived ]
   │        │                                │
   │        ▼                           (پایان مهلت بازیابی)
   │   [ stop_requested ]                    │
   │        │                                ▼
   │   (تایید توقف توسط آژانس)          [ deleted ]
   │        │                                ▲
   ▼        ▼                                │
[ agency_deleted_pending_review ] ───────────┘
       │
 (ثبت نتیجه معامله توسط کاربر)
       │
       ▼
[ deal_result_submitted ]
```

## ۴. ساختار پیشنهادی جداول دیتابیس (Database Schema)

### جدول ۱: `agency_advertise_assignments`
جدول مدیریت ارتباط آگهی و آژانس:
```sql
CREATE TABLE agency_advertise_assignments (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    advertise_id BIGINT NOT NULL,
    agency_id BIGINT NOT NULL,
    consultant_id BIGINT NULL,
    target_type ENUM('agency', 'consultant') DEFAULT 'agency',
    status ENUM('pending', 'approved', 'rejected', 'cancelled') DEFAULT 'pending',
    reject_reason VARCHAR(255) NULL,
    reject_note TEXT NULL,
    cancel_reason VARCHAR(255) NULL,
    expires_at TIMESTAMP NULL, -- مهلت بررسی آژانس (مثلاً ۲۴ ساعت)
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX (advertise_id),
    INDEX (agency_id),
    INDEX (status)
);
```

### جدول ۲: `advertise_stop_requests`
جدول درخواست‌های توقف انتشار ارسال شده از سوی کاربران:
```sql
CREATE TABLE advertise_stop_requests (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    advertise_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    agency_id BIGINT NOT NULL,
    reason VARCHAR(255) NOT NULL, -- معامله انجام شده / منصرف شدم / ...
    description TEXT NULL,
    status ENUM('pending', 'approved', 'rejected', 'cancelled_by_user') DEFAULT 'pending',
    agency_response TEXT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    decided_at TIMESTAMP NULL,
    INDEX (advertise_id),
    INDEX (agency_id),
    INDEX (status)
);
```

### جدول ۳: `advertise_deal_results`
جدول ثبت بازخورد و نتیجه معامله پس از بسته شدن آگهی:
```sql
CREATE TABLE advertise_deal_results (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    advertise_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    agency_id BIGINT NOT NULL,
    consultant_id BIGINT NULL,
    result ENUM('successful', 'unsuccessful') NOT NULL,
    description TEXT NULL,
    feedback_rating INT NULL, -- امتیاز رضایت ۱ تا ۵
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX (advertise_id),
    INDEX (agency_id)
);
```

## ۵. چک‌لیست تست‌های تطابق بک‌اند (Backend Verification Checklist)

- [ ] آیا زمان ثبت آگهی با انتخاب آژانس، وضعیت اولیه آگهی `pending` می‌شود؟
- [ ] آیا اگر آژانس ظرف ۲۴ ساعت پاسخی ندهد، وضعیت به کاربر اطلاع‌رسانی می‌شود؟
- [ ] آیا کاربر در وضعیت `pending` می‌تواند بدون ارور آگهی را لغو کند (`cancel`)؟
- [ ] آیا وقتی آژانس آگهی را رد می‌کند، دلیل رد در آبجکت آگهی ذخیره و برای کاربر در صفحه «در انتظار ثبت مجدد» قابل دسترس است؟
- [ ] آیا در زمان انتشار توسط آژانس، سهمیه پکیج آژانس کسر می‌شود؟
- [ ] آیا هنگام ارسال درخواست توقف از سمت کاربر، پیامک یا اعلان به پنل آژانس ارسال می‌شود؟
- [ ] آیا پس از حذف یا بستن آگهی توسط آژانس، پرچم نیاز به ثبت نتیجه (`wait_for_deal_confirmation`) برای کاربر روشن می‌شود؟
- [ ] آیا ثبت نتیجه در صفحه «نتیجه درخواست»، وضعیت معامله را در دیتابیس قطعی می‌کند؟
